## 記事に書かれていたこと（要約）

**流れ**: 商品情報を渡して「新しい漫画ショート動画を作って」と頼むと、調査 → 戦略 → ストーリー設計 → キャラクターデザイン → コマ画像 → 音声 → 動画 まで進む。実演では依頼から完成まで40〜50分、完成は約60秒の縦型動画。Claude Code が作業し、MCP 経由で自社サービスの機能を使う。人は依頼と確認をする。

**依頼で人が指定したもの**（七宝麻辣湯の例）: 商品URL、作画スタイル、冒頭のテンポ、今回は使わない演出。ストーリー・声・BGM は AI に任せた。

**ストーリーの考え方**:
- 参考にするのは、X や TikTok で話題のテーマ、Instagram で見かける憧れや日常の悩み、ショートドラマや Web 漫画の第1話（話の入り方・展開）
- そこで見つけた話題が、顧客が商品を欲しくなる場面につながるか考える
- **誰が、どんなときに困っていて、どうなりたいのか**を言葉にして AI に渡す
- 例（ゴルフ用品）: 練習ではできるのに同僚とのラウンドでは失敗する／頭では分かっているのに体がついてこない
- 商品URLに書かれていない顧客の情報を知っていれば渡す

**進め方**:
- 最初から全部自分で考えず、まず AI にストーリーを出させ、見ながら直す
- 「完成まで任せる」方法と「工程ごとに確認する」方法がある（例: 「まず商品理解とストーリー案まで」「作画の前にネームを確認させて」）
- **作画や音声の後でストーリーを大きく変えると、作り直す素材が増える。方向性を早めに合わせる**

**完成後の確認**: 人物が同じ人に見えるか／商品の形や使い方が正しいか／商品名を正しく読んでいるか／声が人物に合っているか／台詞・BGM・効果音の重なりやコマの切り替わりに違和感がないか。直すときはコマ番号や台詞と、変えたい内容を具体的に伝える。

## このリポジトリでの対応

| 記事の工程 | このリポジトリ |
|---|---|
| 調査・戦略・ストーリー設計 | `docs/script-method.md`、`templates/script.md` |
| 工程ごとに確認 | 3案を人が選ぶ（第4節）、ダミー絵での確認（`placeholders` / `inspect` / `render`） |
| キャラクターデザイン | `characters[]` → キャラ見本を作り、全コマに渡して顔をそろえる |
| コマ画像 | `manga.py images`（Gemini） |
| 音声 | `manga.py voices`（VOICEVOX） |
| 動画 | `manga.py render` |
| 完成後の確認 | `docs/review.md` |
