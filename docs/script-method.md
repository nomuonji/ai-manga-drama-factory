# 脚本の作り方（AI漫画ショート / AIドラマショート）

どのエージェント（Claude / Codex / ChatGPT / 人）が書いても、同じ順番・同じ基準で脚本を作るための手順書。
**絵や動画の生成より前に、この手順で脚本を確定させる。** 生成はやり直しにお金と時間がかかるが、脚本の書き直しはタダ。

出典つきの根拠は末尾の「根拠」節にまとめた。根拠のない数字や基準は「暫定」と書いてあり、実測で書き換える前提。

---

## 0. 受け取るもの（足りなければ人に聞く）

| 項目 | 例 | なぜ要るか |
|---|---|---|
| 商品・サービス（URL） | 英会話アプリ、AGAクリニック | 何を欲しくさせるか |
| 誰に | 仕事で急に英語が要る20〜30代 | 場面と台詞の現実味 |
| 出口 | LP / 記事 / LINE登録 / 予約 | 最後に何をさせるか |
| URLに書いていない顧客の事情 | 「会議で固まった経験がある人が多い」 | 一番効く場面はたいていここから出る |
| 作風 | 写真漫画 / モノクロ漫画 / カラーWebtoon / 実写ドラマ | 生成プロンプトと尺が変わる |
| 冒頭のテンポ・使わない演出 | 「最初の3秒で事件」「恋愛ネタは使わない」 | 人の好みと商材の制約 |
| 広告規制のある業種か | 医療・美容・健康食品・金融・恋活 | 第8節のチェックが必須になる |

商品URLだけで足りるとは考えない。顧客の事情を知っている人がいれば、その情報が一番価値が高い。

## 1. 商品を1枚にまとめる（商品理解シート）

`productions/<id>/script.md` の「商品理解」欄を埋める。

- その商品で **何が変わるか**（機能ではなく、使った人の日常で変わること）
- それが **他人から見える瞬間** はあるか（見られる・比べられる・褒められる・笑われる）
- 言ってはいけないこと（効果の断定、他社比較の根拠のない優位、価格の誤解を招く表記）

## 2. 顧客の「欲しくなる場面」を探す（欲求喚起シーン）

脚本の出来はここで決まる。**誰が・どんなときに困っていて・どうなりたいのか** を言葉にする。

探す場所（どれか1つで足りないときは複数）:

1. X / TikTok でいま話題が続いている悩み・あるある
2. Instagram で見かける憧れの暮らしと、日常の小さな悩み
3. 人気ショートドラマや Web 漫画の **第1話**（話の入り方と、最初の事件の起こし方）
4. 商品レビュー・Q&A・知恵袋の「使う前はこうだった」

先に `docs/cases/` の事例を1つ以上読み、欲求喚起シーンがどう置かれているかを確かめる。

候補の場面を **10個以上** 書き出し（数は暫定）、次の3点で絞る。

- **体でわかる**: 読んだ人が「うわ、それある」と自分の体験として感じる（説明しないとわからない場面は落とす）
- **他人の目がある**: 自分だけで完結する悩みより、見られる・比べられる場面のほうが強い（暫定の仮説。実測で検証する）
- **商品につながる**: その場面の「どうにかしたい」が、自然に商品へつながる

良い例: 「練習ではできるのに、同僚とのラウンドだと失敗する」(ゴルフ用品)、「会議で海外の取引先を前に固まる」(英会話)
悪い例: 「健康は大事だと気づく」(体でわからない)、「新商品が出た」(欲求がない)

## 3. 型を選ぶ

| 型 | 流れ | 向いている時 |
|---|---|---|
| **A. 5幕** | ①課題・悩み → ②悩みが深刻になる → ③解決策との出会い → ④使った後の変化 → ⑤CTA | 一本で商品紹介まで完結させたい（カルーセル・60秒動画） |
| **B. 第1話クリフハンガー** | ①事件の予兆 → ②気づき → ③衝撃（ドクン・ガーン）→ ▼このあと…▼ | 漫画記事・LPに読ませる前提の短い予告（5〜15秒） |
| **C. 比較（同期・後輩・友達との差）** | ①相手が評判になる → ②自分との差に気づく → ③「何したの？」→ ④秘密＝商品 → ⑤その後 | 見られる・比べられる悩み全般 |
| **D. 意外性** | ①よくある場面 → ②予想と逆のことが起きる → ③理由が商品 | 機能が珍しい商品、話題化を狙う時 |

**最初の1コマ（1カット）で、音なしでも何が起きているかわかる** ことはどの型でも必須。
商品やロゴは最初の数秒に出さない。

## 3.5 フックは本編と別に用意する

参考にしたAIドラマ広告（`docs/cases/20261117-ai-drama-fat-freezing-clinic.md`）は、**本編の前に、物語の時間の外にある7〜8秒のフック素材を付けている。**
明るい部屋で、本編の2人（ぽっちゃりと細マッチョ）が上半身裸でかけ声に合わせて踊る。本編は夜の寝室で、照明も雰囲気もまったく違う。
フックが終わった瞬間、本編の1カット目に題名のテロップ（「〇〇な時ってたぶんこんな感じ」）が出る。

つまり冒頭は3層になっている:

| 層 | 何をするか | 参考事例では |
|---|---|---|
| ① フック素材（2〜8秒） | 物語と切り離した、音なしでも目を止める画。**本編と同じ人物**で、本編の対立（差・悩み）をひと目で見せる | 体型の違う2人が並んで踊る |
| ② 題名テロップ＝約束 | 「この先で何が見られるか」を一文で約束する | 「〜な時ってたぶんこんな感じ」 |
| ③ 本編1カット目 | 約束した状況がもう始まっている | 寝たふりの彼氏と、奥の彼女 |

フックを本編と分ける理由（仮説。成果の数字は外から見えない）:
- 物語の1カット目は状況説明が要るので、目を止める力が弱くなりがち。フックは説明の義務がないので、一番強い画だけにできる。
- **フックだけ差し替えれば、本編はそのままで冒頭違いを何本も作れる**（第9節）。広告では冒頭違いを複数本作って配信しながら選ぶのが基本。
- 同じ人物を使うので、フックから本編へ切り替わっても別の動画に見えない。

**フックの型は `catalog/hooks.json` の一覧から選ぶ**（使い方と増やし方は `docs/hooks.md`。`python3 tools/hooks.py` で一覧が出る）。仕組みの違う型を2〜3個選び、少なくとも1つは実例で確かめた型（`observed`）にする。

フックの作り方:
1. 本編の対立を **体・見た目・行動の差** にして、1つの画にする（並べる・比べる・動きの対比）。
2. 物語の筋（時間・場所）と合わせなくてよい。明るく、動きがあり、少し笑えるものが作りやすい。
3. 2〜8秒。台詞はなくてよい（かけ声・短いテロップ程度）。
4. 最低2〜3種類作る。例: ①見た目の差、②題名だけで約束（顔のアップ＋題名）、③結末を先に見せる（変わった後の姿から始めて「3ヶ月前は…」）。
5. 題名テロップは、フックか本編1カット目のどちらかに必ず置く。

漫画の場合: 参考事例の漫画動画（7.6秒）は、**動画全体が漫画記事・LPへ連れていくためのフック**（「AI漫画バナー × AI漫画記事」）。本編は記事のほうにある。
漫画で1本完結の動画を作るときは、1ページ目をフックとみなし、1ページ目だけ違う版を2〜3種類作る。

ドラマの設計書では `hooks` に書く（`docs/formats.md`）。フックごとに `video-<フックid>.mp4` ができる。

## 4. 3案出して、人に選んでもらう

型と場面の組み合わせで **3案** を作り、それぞれ3行で出す:

```
案1【型C・比較】後輩が急に英語ペラペラに
  冒頭: 海外取引先の前で固まる先輩の顔のアップ
  転換: 後輩がスマホを見せる「通勤中に、これだけです」
  終わり: 3ヶ月後、先輩が自分の言葉で握手 → CTA
```

**3案は、場面・型・感情のどれかが本当に違うものにする。** 人物や小道具を入れ替えただけのものは別案と数えない。
人が選ぶまで、絵や動画は作らない（人が「任せる」と言った場合を除く）。

## 5. コマ割り・カット割りに落とす（ビートシート）

選ばれた案を、1行1コマ（1カット）の表にする。

| # | 何が見えるか（新しく分かること） | 台詞・心の声 | 効果音 | 秒(目安) |
|---|---|---|---|---|
| 1 | 女性2人が誰かを見て笑っている | 「あれ見て…w」「やばいって…w」 | クスクス | 2 |
| 2 | 男が気づく | 「あれ、もしかして…」 | | 1.5 |
| 3 | 男が頭を抱える | 「俺なんか見られてる…？」 | ドクン ドクン | 2 |
| 4 | ▼このあと、大事件が…▼ | | | 1.5 |

ルール:

- **どのコマも、前のコマから新しく分かることが1つある。** 答えられないコマは削る。
- 心が動く瞬間（気づき・衝撃）には **リアクションのコマ** を1つ入れる（顔のアップ、効果音、画面の揺れ）。
- 漫画: 1ページ 3〜5コマ、全体 6〜12コマ（暫定）。ドラマ: 1カット 3〜8秒、全体 30〜120秒（暫定）。
- 最後は「回収」か「続きが気になる終わり方」のどちらかに決める。どっちつかずで終わらない。

## 6. 台詞を書く

- **実際に人が口にする言葉** で書く。説明台詞（「この商品は○○成分で…」）は書かない。
- 吹き出し1つは **縦書き2〜3行・1行3〜6文字**。収まらなければコマを分ける。
- 心の声（考えているだけ）は思考フキダシ、叫びはギザギザ、状況説明はナレーション枠。
- 商品は **登場人物の答え** として出す（「実はさ…」「通勤中に、これだけです」）。宣伝口調にしない。
- 商品名・価格・数字は、読み間違い・誤解がないか声に出して確認する。

## 7. 生成用の設計書（JSON）に変換する

ビートシートを `productions/<id>/manga.json` または `drama.json` に写す（書き方は `docs/formats.md`）。

- 絵の指示（prompt / frame）は **英語** で、**文字を描かせない**。日本語はすべてコードで描く。
- 人物は `characters` に見た目を細かく書く（年齢・髪・服・体格）。毎コマ同じ見本を渡すので顔がそろう。
- 舞台は現実どおりにする（その場所で本当に起きることだけ）。ずらすのは悩みと解決の部分だけ。

## 8. 広告の注意（業種によっては必須）

- 健康・美容・医療: 効果の断定、「治る」「必ず」、使用前後の比較で効果を約束する表現は使わない。医師・専門家を名乗る架空人物を出さない。
- 金融: 利回りの確約、誰でも儲かるような表現はしない。
- 恋愛・人間関係: ストーカー的な行動や、グロテスクな描写は「気持ち悪い・うざい」と嫌われやすいので避ける。
- 実在の人物・有名人・他社のキャラクターを描かない。参考動画の台詞・話・人物をそのまま使わない。
- 最終判断は人がする。規制が厳しい業種は、公開前に人の確認を必ず取る。

## 9. 冒頭違いを複数本つくる

広告では、1本を作り込むより **冒頭（最初の1コマ・最初の3秒）や訴求を1か所だけ変えた版を3〜5本** 用意して、配信しながら効く型を見つけるほうが成果につながりやすい。
- ドラマ: `hooks` にフックを2〜3種類書く（第3.5節）。本編は1回作るだけで、フックの数だけ版ができる。
- 漫画: 設計書を複製し、`hook` と1ページ目だけを差し替える。

## 10. 結果を残す

公開・配信したら `productions/<id>/results.md` に、見られた数・最後まで見た割合・クリック・人の評価（良い／ボツ／理由）を書く。
人が「ボツ」とだけ言った場合、理由を推測で書かない。次の脚本では、良かった案と悪かった案を原文で比べてから仮説を立てる。

- 欲求喚起シーンから考える／探す場所／商品URLにない顧客情報を渡す／まずAIに案を出させて見ながら直す／生成後にストーリーを変えるとやり直しが増える／完成後に絵・声・テンポを確認する:

- 5幕構成（課題→深刻化→出会い→変化→CTA）: ENSOR の漫画クリエイティブ機能の紹介（公募ガイド記事, PR TIMES 由来）https://koubo.jp/article/80335
- ショートドラマで大事な3点（共感できるテーマ、冒頭で物語のテーマがわかる、感情の動きを意識した展開）: DIME, Diffuse 島田貴行氏インタビュー https://dime.jp/genre/1908445/2/
- フック（冒頭3秒）→本編→CTA の3部構成: https://0120.co.jp/blog/video-110/?service=video

- 漫画広告が「気持ち悪い・うざい」と言われる理由（ストーカー要素・グロテスク描写）、規制業種での誇大表現回避: https://mobinc.jp/column/?p=1574 , https://lifestyle.assist-all.co.jp/?p=60598
